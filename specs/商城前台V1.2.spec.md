## 1. 项目定位

| 项 | 内容 |
|---|---|
| 产品 | 商城前台（会员购物端，C 端） |
| 服务对象 | 会员（消费者）与游客 |
| 定位 | 为后台管理系统（B 端，`specs/商城后台管理系统V2.spec.md`）服务的用户入口：浏览商品 → 下单支付 → 订单售后全购物闭环 |
| 形态 | 前后端分离。前端为原生 HTML/CSS/JS 静态页（`front/`），**由独立静态服务托管在 8000 端口**（静态服务站点根=`front/` 目录，页面入口 `http://127.0.0.1:8000/`（根路径即商城首页，无 /front/ 路径；不再挂载在 FastAPI 上））；后端接口服务（含登录与全部 `/api/v1/shop/*` 会员接口）在 **8001 端口**（`http://127.0.0.1:8001`），前台 JS 跨域调用 `http://127.0.0.1:8001/api/v1/shop/*`（后端 `CORS_ORIGINS` 须放行 `http://127.0.0.1:8000` 来源） |
| 现状 → 目标 | 现状：14 页纯静态演示，购物车走 localStorage(`shop_cart_guest`)、金额写死、无任何真实接口；目标：按本 spec 逐页接真实接口至 18 页（S6 新增 after-sale/coupons/points，v1.16 新增 service），购物车/地址/订单/支付/售后闭环真实可跑 |

**一句话目标**：让 `front/` 14 页（+S6 新增 3 页 + 服务中心 1 页共 18 页）从"演示壳"变成"接真数据、真下单、真支付（模拟网关）、真售后"的可用前台，且与后台管理端数据同库联动。

## 2. 技术栈硬约束（不可偏离）

| 领域 | 约束 |
|---|---|
| 前端 | 原生 HTML/CSS/JS，**无构建步骤**（沿用 front/ 现有形态），公共逻辑集中在 `front/js/` |
| 页面目录 | `front/*.html`（14 既有 + S6 新增 3 页 + 服务中心 1 页 = 18 页，两级内），静态资源 `front/css/style.css`、`front/js/main.js`、`front/images/` |
| 后端 | 复用 FastAPI 服务与 MySQL 表（goods/orders/members/coupons…），**不新建库** |
| 接口前缀 | 会员端全部走 `/api/v1/shop/...`，与后台 `/api/v1/auth|permission|goods|orders|member|...` 隔离，禁止共路径 |
| 认证 | 会员 JWT（`Authorization: Bearer <token>`），与后台 admin JWT **隔离签发**（见 §4.4） |
| 密码 | members.password_hash 复用后台 bcrypt 体系 |
| 金额 | 一律 DECIMAL(10,2)，页面展示保留两位；运费/优惠在**前端只读展示、服务端结算** |
| 禁止 | ① 前端本地写死商品/金额/库存做真业务；② 前端自行算应付金额（必须服务端结算为准）；③ 直接复用 B 端带权限码接口给游客/会员调用 |

## 4. 全局接口契约（复用后台 V2 spec §4）

### 4.1 统一返回格式 / 分页 / 字段命名
- 响应 `{ code, message, data }`；HTTP 与 code 独立；分页 `data:{ list, total, page, page_size }`——**全部复用后台 spec §4.1/§4.2**。
- API 传输 camelCase、库字段 snake_case，前端不做适配（后端 service 层已转换）。
- **C 端实现基准注（2026-09-03 验收定稿）**：§5 全部契约由前台里程碑在后端新增 `shop_*.py` 路由实现（含 previewToken、pay 模拟等 C 端专属机制，见 §5 引言），后台既有代码零改动；后台现有 B 端实现存在"入参 snake_case、出参 camelCase"的实际出入（评审 A1，定稿决策不回写后台）——**C 端新增接口入参/出参一律以本 spec §5 的 camelCase 契约为准**，不继承 B 端该出入，避免同一 codebase 双约定。
- 列表通用参数：`page`、`page_size`、`keyword`、`sort_field`、`sort_order(asc|desc)`。

### 4.2 路由规范
- 统一前缀 `/api/v1/shop/{resource}`，资源复数。
- 动作型：`POST /api/v1/shop/{resource}/{id}/action`。
- **无导出**（C 端不需要）。

### 4.3 会员认证（C 端专用，与 B 端隔离）
- 登录：`POST /api/v1/shop/auth/login`，入参 `{ phone, password }`，返回 `{ token, member:{...} }`。
- token 鉴权依赖：登录态 →（无 B 端权限码概念，仅校验会员状态启用/禁用）。
- JWT 载荷建议含 `typ:"member"`（与 B 端 `typ:"admin"` 区分）与 `member_id`、`phone`；同一 JWT_SECRET 或独立 MEMBER_SECRET 均可（配置文件新增项，见 §11 配置）。
- 游客接口（首页/搜索/详情/加购预览）不需要 token；进入结算/下单/地址/订单等页前端跳登录（`login.html?redirect=...`），后端对应接口强制校验。

### 4.4 错误码字典（复用 + C 端新增）

| 错误码段 | 含义（沿用后台） | 前端处理 |
|---|---|---|
| 0 | 成功 | - |
| 1001–1003 | 认证类（token 无效/未登录/锁定） | 1001/1002 跳登录（带 redirect）；1003 提示 |
| 2001–2002 | 参数校验失败/分页越界 | 表单高亮/提示 |
| 3001–3005 | 3001 库存不足 / 3002 状态不允许 / 3003 关联不可删 / 3004 重复数据 / 3005 营销优惠不可叠加（区别于 3007 券不可用） | 业务分支提示 |
| 4001 | 无权限（本端基本不出现，B 端专属） | 通用提示 |
| 5000 | 服务器内部错误 | 通用错误提示 |
| **3006** | **订单已超时/不可操作（C 端新增）** | 跳订单列表并提示重新下单 |
| **3007** | **优惠券不可用（未领取/不在期/门槛不足/已使用，C 端新增）** | 结算页提示并刷新可用券 |
| **3008** | **超出限购数量 buy_limit（C 端新增）** | 调整数量后重提 |

## 5. C 端接口契约清单（新增设计，后端据此开发）

> 下表为前台联调所需的 C 端契约（设计阶段 B 端 V2 spec §5 尚无会员接口，故作为新增契约提出）；**现已全部实现**，落位于 `backend/app/routers/shop_*.py`（共 10 个 shop_* router）。接口字段名 camelCase；加 `[登录]` 的需会员 token。

### 5.1 认证 auth（表 members / member_logs）
| 方法 | 路径 | 登录 | 说明 |
|---|---|---|---|
| POST | /api/v1/shop/auth/send-code | - | 发送短信验证码 `{phone, scene: register}`（**V1 仅注册场景使用**，scene 枚举收敛为 register，见下表注；频率校验 60s）。实现口径（2026-10-08 修订）：验证码用 CSPRNG 随机生成 6 位，BCrypt 哈希落 `sms_codes` 表，含 5 分钟过期与 5 次错误上限；`SMS_MOCK=true` 时不真实下发，明文随响应字段 `devCode` 回显；`SMS_MOCK=false` 时直接返回业务错误（未接入服务商）。**不存在任何固定验证码** |
| POST | /api/v1/shop/auth/register | - | 注册 `{phone, code, password}`；手机号唯一（已存在回 3004）；写 members + 积分？(默认 0)；写 member_logs；成功可返回 token 或跳登录 |
| POST | /api/v1/shop/auth/login | - | 登录 `{phone, password}` → `{token, member}`；连续失败锁定策略复用后台（可选） |
| GET | /api/v1/shop/auth/me | ✅ | 当前会员 `{id, nickname, avatar, phone, email, levelId, levelName, points, totalConsume}` |
| PUT | /api/v1/shop/auth/password | ✅ | 改密码 `{oldPassword, newPassword}` |
| PUT | /api/v1/shop/auth/profile | ✅ | 改资料 `{nickname, avatar}` |
| POST | /api/v1/shop/auth/logout | ✅ | 退出（写 member_logs） |

> 认证策略注（2026-09-03 评审定稿）：① 登录为手机号+密码，**无验证码登录**，scene 仅 register；send-code 的 login/bind 场景 **V1 不提供**（后续版本需验证码登录/换绑手机时再行扩展）；② **V1 无 C 端"忘记密码/短信重置密码"**：改密码须旧密码（PUT /auth/password）；密码遗失由后台管理员在会员管理重置（后台已具备），前端仅提示"联系客服/后台重置"。

### 5.4 购物车（表新增 `member_cart`，见 §6；游客态由前端 localStorage 承接，见 §8 页面逻辑）
| 方法 | 路径 | 登录 | 说明 |
|---|---|---|---|
| GET | /api/v1/shop/cart | ✅ | 我的购物车列表：`{list:[{id, goodsId, skuId, goodsName, specText, price, image, quantity, stock}], totalCount, selectedCount, totalAmount}` |
| POST | /api/v1/shop/cart | ✅ | 加入 `{goodsId, skuId, quantity}`；已存在则数量累加；校验上架与库存上限 |
| PUT | /api/v1/shop/cart/{id} | ✅ | 改数量 `{quantity}`（≥1） |
| PUT | /api/v1/shop/cart/selected | ✅ | 勾选状态 `{ids:[], selected:bool}`（全选/单选复用） |
| DELETE | /api/v1/shop/cart/{id} | ✅ | 删除单条 |
| POST | /api/v1/shop/cart/merge | ✅ | 登录后合并游客本地购物车 `{items:[{goodsId,skuId,quantity,selected}]}`（selected 缺省按 1 处理；与本地项逐条对应，避免丢勾选态） |
| DELETE | /api/v1/shop/cart | ✅ | 清空（下单成功后清所选） |

> 登录态购物车以**服务端为准**；游客购物车存 localStorage（键 `shop_cart_guest`）。**合并时机统一为 login 成功即触发（见 §8.13）**：本地游客车非空 → 先 `POST /cart/merge` 合并成功并清本地 → 才执行 `redirect` 回跳，保证"游客加购→登录→回结算"链路购物车不丢。

### 6.1 member_address 会员收货地址
```sql
CREATE TABLE IF NOT EXISTS member_address (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  member_id BIGINT UNSIGNED NOT NULL,
  receiver_name VARCHAR(50) NOT NULL,
  receiver_phone VARCHAR(20) NOT NULL,

  city VARCHAR(50) NOT NULL,
  district VARCHAR(50) NOT NULL,
  detail VARCHAR(200) NOT NULL,
  is_default TINYINT NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_address_member (member_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 6.2 member_cart 会员购物车
```sql
CREATE TABLE IF NOT EXISTS member_cart (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  member_id BIGINT UNSIGNED NOT NULL,
  goods_id BIGINT UNSIGNED NOT NULL,
  sku_id BIGINT UNSIGNED NOT NULL,
  quantity INT NOT NULL DEFAULT 1,
  selected TINYINT NOT NULL DEFAULT 1,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_cart_member_sku (member_id, sku_id),

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 6.3 region 区域字典
```sql
CREATE TABLE IF NOT EXISTS region (
  code VARCHAR(20) NOT NULL PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  parent_code VARCHAR(20) NOT NULL DEFAULT '',
  level TINYINT NOT NULL COMMENT '1省 2市 3区/县',
  sort INT NOT NULL DEFAULT 0,
  KEY idx_region_parent (parent_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
> region 属**基础字典数据**，仅入 seed `base`（**禁止放 demo**，demo 可整删会删掉功能字典）。治理约定：①seed 与业务零耦合——启动不执行，生产仅初始化/版本发布时人工 `python -m seed.runner base`，不影响运行库；②base 幂等以 `code` 为主键 upsert，不删不重置，生产已有库重复执行安全；③V1 仅 seed 演示子集（广东/北京/上海含下级各 2~3 项），全国全量区划属后续版本发布追加 base 数据，接口与前端零改动；④若将来区划需运营在后台**即时维护**（不走代码发布），届时将 region 从 seed 剥离、改由后台维护功能管理，seed 全量仅作首次基线。

> 短信验证码落 `sms_codes(phone, scene, code_hash, expires_at, used_at, fail_count)` 表（已实现，为第 46 张表）。
> 历史写法「演示环境固定验证码（如 123456）则不必建表」已废止：固定码等于公开注册后门，必须建表并随机发码。

## 8. 逐页前端逻辑设计（现状 → 目标改造点）

> 通用约定：① 所有页统一注入公共 `front/js/main.js`（含 request 封装/登录态/购物车角标/toast/弹层，见 §9）；② 页面私有逻辑以 `data-page` 或独立 init 函数承载；③ 跳转带参一律 URL query（`detail.html?id=`、`search.html?keyword=&categoryId=`、`orders.html?tab=`、`payment.html?orderNo=`），不依赖内存态刷新丢失。

### 8.1 index.html 首页
- **现状**：分类/轮播/楼层/商品卡全写死，零 JS 渲染。
- **目标逻辑**：加载时 `GET /api/v1/shop/home` → 渲染：轮播(banners)、侧栏分类树(categories)、楼层商品（recommend/hot/newArrival 按现有 .product-grid/.product-card 模板）。点击分类/商品/广告按 query 跳 search/detail。
- **分类菜单点击口径（2026-09-22 定稿决策，v1.11 收紧为纯点击）**：**hover 不展开面板**；有子级的父分类**点击=展开**（不渲染 `<a href>`、不跳转，main.js click 拦截 preventDefault），**再点同一项=收起，点其他父项=切换，点菜单外任意处=收起**；子分类面板内仅**叶子**分类（无 children）为可跳 `<a href="search.html?categoryId=">`，中间层分类条目为 `<span>` 不可跳；无子级的一级分类保持 `<a>` 直接跳转。
- **购物车角标**：登录读 `/api/v1/shop/cart` 计数；游客读 localStorage。

### 8.2 search.html 搜索/列表
- **现状**：20 条写死 products，筛选排序是假 UI。
- **目标逻辑**：读 `?keyword=&categoryId=&brandId=&minPrice=&maxPrice=&tag=` 初始化 → `GET /api/v1/shop/goods`（page/page_size）；侧栏分类/品牌来自 §5.3 接口；顶部排序（综合/销量/价格升降/新品）与筛选变更 → 重新请求并拼回 URL；分页渲染 .pagination。结果项 → `detail.html?id=`。
- **父分类筛选口径（2026-10-04 缺陷修正，v1.13）**：`categoryId` 允许指向**任意层级分类**（含父分类）——后端按分类子树过滤（`shop_catalog.py _category_subtree_ids`），前端不再把父分类回落成"全部商品"；侧栏分类树中父分类与叶子一样可选中高亮，选中父分类同时自动展开其子级；点击分类行的箭头 `›` = 仅展开/收起子级、不改变筛选；顶栏主导航（§8.3）映射到的父分类（电视/家用电器等）进列表页后与侧栏高亮联动一致。"全部商品"仅在 `categoryId` 为空时高亮，且面包屑隐藏重复的"全部商品 /"段。
- **产品线导航口径（2026-10-05 对齐主流电商通用口径，v1.14）**：①顶栏主导航项=**产品线入口**，固定映射到命中分类所属的一级分类（`main.js rootOf` 逐级上溯）；②列表页当前分类上溯后对应的顶栏项 `.active` 高亮；③列表页在排序栏上方渲染**二级子分类横排**（`全部<父分类名>` + 直属子分类胶囊，同为 hover 浅米 / 选中渐变橙白字 13px 圆角 8px 视觉语言），点子分类=按该子分类过滤，点"全部XX"=回到父级子树，未选分类时横排隐藏；④面包屑显示「父分类 / 子分类」层级。

### 8.3 detail.html 详情
- **现状**：单商品写死，规格仅"版本/颜色"两静态组，加购写 localStorage + 跳 add-to-cart。
- **目标逻辑**：`?id=` → `GET /api/v1/shop/goods/{id}` 渲染图/价/规格；规格选择联动出可用 SKU（价/库存/图），选中后才能加购/立即购买；未选规格按钮 disabled。**无规格商品（specs=[]）：接口必须返回其默认 SKU 行（specValueIds/specText 为空），前端首屏即选中该 SKU——按钮直接解禁、tip 显"库存 N 件"（2026-09-22 bug 卡⑥定稿）**。
- **顶部主导航口径（2026-09-22 定稿决策"不要假链接"）**：index/search/detail `.main-nav` 七项由 `main.js initMainNav()` 按 `NAV_ALIAS` 映射真实分类树写 `search.html?categoryId=<id>`（先精确后包含匹配）；服务中心/社区无对应分类保持 `#`；接口失败保持原 href 不阻塞。
- **加购**：游客 → 写 `shop_cart_guest` 后跳 `add-to-cart.html?goodsId=&skuId=`；会员 → `POST /api/v1/shop/cart` 成功后跳。库存不足/下架 → toast 提示（3001/3002）。
- **立即购买**：登录后 `POST /api/v1/shop/orders/preview {type:'buy'}` 直入 checkout（bypass 购物车）。
- **评价区**：Tab 加载 `GET /goods/{id}/comments`（好评率/列表/商家回复）。

### 8.4 add-to-cart.html 加购成功
- **现状**：静态成功页 + 猜你喜欢静态。
- **目标逻辑**：读 query 展示刚加购商品快照（名称/规格/价/数量），"去购物车结算"→ cart.html；"继续购物"→ 回来源；猜你喜欢调推荐商品接口。
- **落地注（2026-09-05 S2）**：快照以 `GET /goods/{id}` 服务端真值渲染（不读本地车，避免本地数据被清后无法展示）；"继续购物"目标由 `?from=` 决定，缺省 `index.html`，仅放行站内 `.html` 相对路径（来源由 detail 页加购跳转附带）；猜你喜欢走 `GET /goods?is_recommend=1&page_size=5`。

### 8.5 cart.html 购物车
- **现状**：localStorage 演示注入 3 件。
- **目标逻辑**：游客读 `shop_cart_guest` 渲染并本地改选/数量/删；会员 `GET /api/v1/shop/cart` 渲染，改选/数量/删/全选 → 对应接口（乐观更新失败回滚）；合计区用服务端返回金额或本地按项算（仅展示，最终以 preview 为准）；去结算校验选中>0 → 登录则 checkout.html，未登录先登录跳回。空车显示空态。
- **落地注（2026-09-05 S2）**：① 两态共用同一份行模板与合计口径（游客按本地项、会员按服务端 list 本地重算，**仅展示**，最终以 preview 为准）；② 勾选/数量/删除均"本地即时更新 + 接口提交"，接口失败 toast 后回滚重取服务端真相；③ 游客车非空时页面顶部提示"登录即自动合并"，去结算（未登录）跳 `login.html?redirect=cart.html`，登录后回本页展示合并结果（S3 结算页落地后去结算目标为 checkout.html）；④ 本页不再引入 `main.js` 的旧演示购物车逻辑（`ShopCart`），改由 `js/page-cart.js` 承载。

### 8.6 checkout.html 结算确认（合并现 checkout/address 两态为一份确认页）
- **现状**：checkout 无地址 alert、address 有地址卡可提交，金额写死不读购物车。
- **目标逻辑**（重构为单页确认）：进入先校验登录 → 有"立即购买直购单"则按直购项，否则取购物车选中项 → `POST /orders/preview` 拿服务端价格清单。
  - 地址区：默认地址卡片；无地址显空态按钮 → `address-add.html`；点卡片可进 `address.html` 切换；点"修改"→ `address-edit.html?id=`。
  - 商品清单渲染 preview.items；金额区：商品总额/运费/券减/积分抵/应付=preview.payAmount（**只展示**）。
  - 可用优惠券下拉/勾选（preview.availableCoupons）→ 重调 preview 带 couponId；积分抵扣同（前端只开关，服务端结算）。

### 9.5 实时自动更新（live.js）

- 目的：后台改数据 / 改 `front/` 静态样式结构后，前台页面自动反映，无需人工刷新（样式类→无感热更；结构/数据类→自动整页刷新）。
- 后端：`GET /api/v1/shop/live/version`（公开）。`assets.css/html/js` 各为 `front/` 下对应扩展名文件 (相对路径,size,mtime_ns) 排序拼接的 sha256 前 32 位；`data` 为内容表白名单（goods/goods_sku/goods_category/brands/specifications/specification_values/goods_images/goods_comments/ad_positions/ads/notices/articles/article_categories/coupons/seckill_activities/full_discount_activities/group_buy_activities）按 `COUNT(*)`+`MAX(id)`+`MAX(updated_at)`（列缺失自动降级）聚合的指纹。结果 2s 进程缓存，前台多标签共享一次请求成本。
- 数据表约束：goods_category/specifications/specification_values/goods_images/article_categories/ad_positions 6 表需有 `updated_at` 列（`backend/seed/schema.py` 已补，`ensure_content_updated_at()` 幂等补列，`python -m seed.runner base` 生效）。
- 关闭开关：URL `?live=0` 或 `localStorage.setItem('shop_live','off')`；刷新间隔默认 4000ms，可用 `localStorage.shop_live_interval` 调整。

## 10. 核心业务规则约束（与后台 spec §10 对齐 + C 端补充）

1. **商品可见性**：列表/详情/加购仅面向 `goods.status=1`（上架）；下架/删除商品详情与接口回 3002/404。
2. **价格口径**：展示价以 SKU.price 为准；商品页"立即购买/加购"必须以所选 SKU 提交，禁止无规格提交。
3. **结算**：运费/优惠/积分抵扣全部**服务端按 preview 计算**（freight_templates/满减/优惠券/points_discount_ratio），前端只透传选择项，禁止前端算应付。
4. **下单**：复用后台 §10.2 原子库存扣减；同一事务写 orders/order_items/order_logs、扣 coupon_receive/积分、清购物车所选；失败整体回滚。
5. **订单状态机**：与后台 §10.1 完全一致（1→2→3→4；1 可取消→5；2/3/4 可售后→6）。C 端允许操作：1 取消/支付；3 确认收货；**2/3/4 按规则 8 边界发起售后（1 待付款/5 已取消不可）**。状态流转写 order_logs（operator_type=1 用户）。
6. **支付超时**：待付款订单超过 `config.order_pay_timeout`（默认 14 分钟，与现 payment 页倒计时一致）未支付 → 系统任务/懒更新置 5 已取消并**回补 SKU 库存**。
7. **限购**：goods.buy_limit>0 时同用户累计购买数（在途+已完成）不得超过，超限回 3008。
8. **售后窗口（边界定稿，2026-09-03）**：

| 订单状态 | 可发起售后 |
|---|---|
| 1 待付款 | 不可（只能取消订单） |
| 2 待发货 | 仅退款（type=1） |
| 3 已发货 / 4 已完成 | 仅退款（type=1）或退货退款（type=2） |
| 5 已取消 | 不可 |
| 6 售后中 | 不可（同订单已有进行中售后禁止重复发起） |

售后窗口闭环：订单进入售后中(6)后——售后**撤销/被拒** → 订单回落发起前状态（2/3/4，相应操作恢复，可再次发起）；售后**完成** → 订单回到业务终态语义（演示不扩展真实退款财务域，订单状态机不新增值，流转写 order_logs），S6 实现按本条与后台核对口径。

9. **营销叠加**：与后台 §10.3 一致；秒杀/拼团商品在预览中标记且不参与优惠券/满减（字段由 preview 返回提示）。
10. **会员评价**：开放，作为迭代 **S5** 独立功能卡（§13）实现——仅"已完成(4)"订单本人可对购买商品评价一次（评分 1~5 + 文本），同订单同商品不重复；写 goods_comments(status=0 待后台审核，order_id 落单号)，后台 goods-comment 页既有审核流直接管辖；C 端列表仅展示 status=1 已通过。排期理由：评价合法性校验依赖 S4 真实订单链路（买→付→发→收）跑通后才有数据，故排 S5 而非提前。

## 12. 验收标准（Definition of Done）

### 12.1 页面功能（18 页逐一）
1. **首页**：home 接口渲染轮播/分类/楼层/公告，无写死商品。
2. **搜索**：URL 参数→接口→筛选/排序/分页/空态全可用。
3. **详情**：规格选择联动 SKU 价/库/图，加购与立即购买可用，越权/下架正确提示。
4. **注册/登录**：验证码 60s、协议控制、登录态持久化、redirect 回跳。
5. **购物车**：游客 local 与会员服务端两态正确切换合并，改选/数量/删/全选可用。
6. **结算**：服务端 preview 金额与下单一致；地址增改选、优惠券/积分选择后金额刷新；库存不足 3001 分支可见。
