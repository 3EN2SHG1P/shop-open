# 商城后台管理系统 - 静态页面

基于《商城后台管理系统V2.spec.md》需求规格生成的完整后台管理静态页面。

## 快速开始

直接用浏览器打开 `login.html` 可预览静态样式（无需构建工具；但登录联调必须先启动后端，见下文联调提示。联调时由后端统一托管：启动 `backend` 后访问 `http://127.0.0.1:8001`，根路径自动跳转到本登录页）。

- 登录页：`login.html`（演示账号 `admin`，初始口令由 `seed base` 生成并打印；可在 `.env` 用 `ADMIN_INIT_PASSWORD` 指定，重跑 `seed base` 会按该值同步。登录成功写入本地会话）
- 仪表盘：`dashboard.html`（登录后默认跳转页）

登录/退出逻辑：

- 登录成功后以当前账号为准渲染顶栏用户信息（姓名/角色/账号），未登录直接访问子页面会跳回登录页。
- 顶栏右侧用户区为下拉菜单，可执行「退出登录」清除会话并返回登录页。

## 技术栈

- **HTML5** — 语义化结构
- **CSS3** — 完全独立样式文件，CSS变量主题系统
- **原生 JavaScript (ES6+)** — 无框架依赖，模块化公共组件
- **响应式布局** — 适配桌面端、平板、移动端

## 与 Spec 文档的对应

本页面严格按照 `specs/商城后台管理系统V2.spec.md` §8 "页面-路由-权限码映射" 生成，覆盖全部 P0/P1/P2 模块：

- ✅ RBAC 四层权限（菜单/按钮/接口/数据）UI 对照
- ✅ 仪表盘指标口径（今日订单/GMV/新增用户/待付款/待发货/库存预警）；转化率与商品浏览量在 spec 中有口径定义，当前仪表盘未实现
- ✅ 商品整单提交结构（基本信息+SKU+图片+SEO；运费模板字段当前固定提交 `null`，未接入模板选择）
- ✅ 订单状态机（待付款→待发货→已发货→已完成）
- ✅ 售后审核流程（仅退款/退货退款）
- ✅ 会员等级体系与积分流水
- ✅ 营销叠加规则的 UI 表达（优惠券+满减可叠加、秒杀/拼团不可叠加由前端下拉与提示体现；**活动叠加 `is_stackable` 未接入结算引擎**，实际结算只走优惠券与积分）
- ✅ 系统设置（基本/支付/物流/通知/运费模板）
- ✅ 操作日志七类（登录/新增/修改/删除/导出/审核/退出）

> 联调提示：`login.html` 直接双击打开无法登录，必须先启动后端（8001）提供 `/api/v1/auth/login`。

## 数据说明

全部 28 个页面（26 个功能页 + 登录页 + 仪表盘）均已接入真实后端接口（增删改查/筛选/导出均真实落库），接口契约遵循 spec §4-§5 与 `/api/docs`。

自动化回归未覆盖 `marketing` / `content` / `settings` / `admin_logs` 四个模块，这部分的正确性目前依赖人工验证。

登录会话存于 `localStorage`（key 见 `js/common.js`），顶栏用户信息取自会话，不在页面中写死。注意这意味着任何 XSS 都可能窃取令牌 —— 本项目把它列为已知边界，生产应改用 httpOnly Cookie。

列表回填编辑表单统一走 `AdminUI.findRow()`：列表请求返回时按接口缓存行数据，「编辑」优先从缓存取，取不到才退化查询，避免记录数超过单页后在列表里「点编辑没反应」。
