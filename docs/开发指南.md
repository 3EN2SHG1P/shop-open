## 1. 架构总览

### 1.1 三层职责

| 层 | 目录 | 干什么 | 不干什么 |
|---|---|---|---|
| 路由层 | `backend/app/routers/` | 参数校验、鉴权声明、编排、返回包装 | **不写 SQL、不写业务** |
| 服务层 | `backend/app/services/` | 业务逻辑、手写 SQL、`snake_case ↔ camelCase` 转换 | **不碰 Request/Response** |
| 基础设施 | `backend/app/core/` | 配置 `config`、连接池 `database`、鉴权 `deps`、密码/令牌 `security`、错误码 `errors`、响应包装 `response` | — |
| 入参模型 | `backend/app/schemas/` | Pydantic 入参校验（只有入参，不做出参模型） | — |
| 数据初始化 | `backend/seed/` | 建表 `schema.py`、基础数据 `base.py`、演示数据 `demo.py` | **不参与运行时**（启动不会执行） |

没有 ORM，全部手写 SQL，`WHERE` 条件一律用 `%s` 参数化。

### 1.2 一次请求的生命周期

```
HTTP → main.py（路由自动扫描）
     → Depends(get_current_user)      解析 JWT、查管理员、校验状态
     → Depends(require_permission)    校验权限码
     → service 层（业务 + SQL + 数据权限）
     → ok()/page_data() 统一包装 → { code, message, data }
```

异常路径：`services` 抛 `BizError`（`core/errors.py` 的 `bad_request/not_found/state_error/...`），
由 `main.py` 的异常处理器转成统一 JSON；未捕获异常记 `logging` 并返回 `code=5000`。

### 1.3 两个端口、两个前端

| 端口 | 内容 | 说明 |
|---|---|---|
| 8001 | 后端接口 + 后台管理端 `manager/` | 同源，无跨域 |
| 8000 | 商城前台 `front/` | 纯静态，跨域调 8001 |

`manager/` 由后端 `/manager` 静态托管，`uploads/` 由 `/uploads` 托管（**均无鉴权**，生产请交给 Nginx）。

## 2. 目录与命名约定

| 位置 | 约定 |
|---|---|
| `backend/app/routers/xxx.py` | 必须定义模块级 `router = APIRouter(prefix="/api/v1", tags=["xxx"])` |
| `backend/app/services/xxx.py` | 函数即用例：`list_xxx / get_xxx / create_xxx / update_xxx / delete_xxx` |
| `backend/app/schemas/xxx.py` | 入参模型；出参在 service 里手写 dict |
| `manager/pages/<模块>/<页>.html` | **固定两级**，公共样式引 `../../css`、脚本引 `../../js` |
| `front/<页>.html` + `front/js/page-<页>.js` | 前台逐页脚本，公共能力在 `api.js`/`ui.js`/`main.js`/`auth.js` |

字段命名：**query 用 `snake_case`，请求体与响应用 `camelCase`**，转换只在 service 层做（用 `core/common.row_to_camel`）。

## 3. 任务 A：新增一个后台接口

1. `schemas/<模块>.py` 加入参模型（金额字段以 `float` 传输，计算前必须用 `core/money.py` 量化，见 §7 坑位）
2. `services/<模块>.py` 加业务函数：写 SQL、做 camelCase 转换、抛 `core.errors` 里的错误
3. `routers/<模块>.py` 加路由：`@router.get("/xxx")`，`user=Depends(P("<权限码>"))`，`return ok(await svc.xxx(...))`
4. 权限码：若为新码，在 `seed/base.py` 的 `MODULES` 里加（→ 自动生成进 `PERM_TREE`）
5. 重跑 `python -m seed.runner base`（权限树已幂等，已有库也会补齐新码并自动授予 admin 角色）
6. 补测试：`backend/tests/` 加用例

> 路由是 `main.py` 用 `pkgutil` 自动扫描注册的，**不要手改 main.py**；新建文件并导出 `router` 即可。
> 注意通配路径（如 `/goods/{id}`）必须声明在具体路径（如 `/goods/export`）之后。

## 4. 任务 B：新增一张表 + seed 数据

1. `seed/schema.py` 的 `TABLES` 里追加 `CREATE TABLE IF NOT EXISTS`；业务表建议带 `created_at/updated_at/created_by`
2. `seed/base.py` 的 `seed_dict()` 加字典数据，或 `seed/demo.py` 加演示数据
3. demo 数据必须幂等：`INSERT IGNORE` / `ON DUPLICATE KEY UPDATE` / 先查哨兵再插（重跑不翻倍）
4. `python -m seed.runner base`（建表）；演示数据 `python -m seed.runner demo`
5. **已有库加列不会自动生效**：`CREATE TABLE IF NOT EXISTS` 不改已有表。需手写一次性 `ALTER`，
   或仿照 `schema.ensure_content_updated_at()` 写幂等补列函数并在 `runner.create_tables()` 里调用

## 5. 任务 C：新增一个后台功能页

必须同步 4 处：

1. `manager/pages/<模块>/xxx.html`（两级目录不要变）
2. `manager/js/common.js` 的 `menuData` 加菜单项
3. `manager/js/common.js` 的 `MENU_PERM` 加权限前缀 —— **漏了菜单会被隐藏**（`menuVisible` 是 fail-closed）
4. 页面里 `AdminUI.initPage({ key: 'xxx' })` 的 `key` 必须与 `menuData.key` 完全一致，否则高亮/面包屑失效

若用到新权限码，还要同步 §3 的第 4~5 步。

## 6. 任务 D：新增一个前台页或 C 端接口

C 端接口前缀固定 `/api/v1/shop/*`，用会员令牌（`shop_auth.py` 系列），**没有权限码**。

1. `front/<name>.html` + `front/js/page-<name>.js`
2. 页面内脚本顺序固定：`ui.js` → `api.js` → `auth.js` → `main.js` → `page-<name>.js` → `live.js`（`main.js` 提供分类菜单等公共交互，勿漏）
3. 接口统一走 `window.ShopRequest`（`api.js`），**不要裸 fetch**；所有插值用 `ShopUtil.esc()`，
   富文本（如商品详情）用 `ShopUtil.sanitizeHtml()`
4. 需要登录的页，在 `auth.js` 的 `NEED_LOGIN` 里加一项
5. 顶栏/页脚目前是每页硬编码的（已知待优化，见 §8），改导航记得全量替换

## 7. 不能踩的坑（每条都对应真实代码位置）

| # | 坑 | 位置 |
|---|---|---|
| 1 | 路由靠 `pkgutil` 自动扫描，勿手改 `main.py` | `app/main.py:register_routers` |
| 2 | 必须在 `backend/` 目录执行 seed 与 `run.py` | README §3.6 / §3.7 |
| 3 | query=snake_case、body/响应=camelCase，转换只在 service 层 | `core/common.row_to_camel` |
| 4 | **金额计算统一走 `core/money.py`**（`Decimal` + `ROUND_HALF_UP`，量化到分）；对外 JSON 仍输出 `float` 以兼容前端。各 service 里的 `_money` 是 `core.money.f2` 的别名，不要再写本地 `def _money`。**库存扣减分两层**：SKU 级是单语句条件扣减 `UPDATE ... WHERE stock >= N`（不足即失败，卖不出负数），只有商品级汇总库存用 `GREATEST(stock-N,0)` 兜底；两层都在同一事务内，但无分布式锁 | README §10 已知限制 |
| 5 | 双 JWT：后台 `typ=admin`、会员 `typ=member`，两端令牌不通用，解码时会校验 `typ` | `core/security.py` |
| 6 | 全库时间是东八区字面量，写 `DATETIME` 用 `core.timezone.now()` / `to_naive()` | `core/timezone.py` |
| 7 | 事务内只能用 `async with database.transaction() as cur` 里的 `cur`；**调 `database.fetch_*` 会另取连接，不在同一事务**（池满时还会死锁） | `core/database.py` |
| 8 | SQL 必须参数化；排序方向等无法参数化的部分必须白名单化 | `services/shop_catalog.py` |
| 9 | 权限缓存 300s，改角色/权限后需 `invalidate_user()`，否则最多 5 分钟后生效 | `core/deps.py` |
| 10 | 换端口要同步三处：`.env` 的 `CORS_ORIGINS`、`UPLOAD_PUBLIC_BASE`（改后重跑 demo）、前台 `localStorage.shop_api_base` | README §9 FAQ |
| 11 | 调试前台时 `live.js` 会自动刷新页面，用 `?live=0` 关闭 | `front/js/live.js` |
| 12 | 业务表要带 `created_by`，否则数据权限（1 仅本人 / 2 本部门及子部门 / 3 全部）失效 | `core/deps.py:data_scope` |
| 13 | 密码上限 72 字节（bcrypt 静默截断），入参已在 schema 层收紧 | `core/security.py` |
| 14 | `seed base` 已初始化后不会重建角色，但会幂等补齐权限树/字典数据；新增权限码或配置项直接重跑即可 | `seed/base.py` |
